# Project Time Machine 0.7.6 — Linux

## Установка

Нужны Linux kernel 5.3+, Python 3.11–3.13 с venv, tar/gzip и интернет для зависимостей.
На Ubuntu: `sudo apt install python3-venv`. Сам установщик запускайте обычным пользователем,
без sudo. Python, уже установленный через uv, находится автоматически.

В папке комплекта:

```sh
sha256sum -c SHA256SUMS
tar -xzf project-time-machine-0.7.6-linux.tar.gz
cd project-time-machine-0.7.6
./install.sh
```

Архив можно распаковать где угодно. Приложение устанавливается в `$HOME/ProjectTimeMachine`,
данные находятся отдельно от releases с кодом. Другие папка/порт:

```sh
./install.sh --prefix "$HOME/MyPTM" --port 13021
```

Стандартный порт 13011; если он занят, выбирается свободный. Явный занятый порт даёт ошибку.
`--no-start` готовит установку без запуска. `--wheelhouse /absolute/wheels` использует
локальные пакеты. Системные службы/firewall не меняются; root не нужен. Установщик
выполняет встроенную самопроверку на временных данных.

## Прямой доступ через интерфейсы

По умолчанию слушаются **все IPv4-интерфейсы — 0.0.0.0**. Установщик печатает реальные
URL интерфейсов. Откройте в браузере `http://АДРЕС_СЕРВЕРА:ПОРТ`: Ethernet/Wi-Fi/VPN,
включая адреса 100.64.0.0/10. SSH-туннель и ручной список разрешённых подсетей не нужны.
**0.0.0.0 — bind, а не адрес для браузера.** Для IPv6 выбирается bind `::` в настройках.

HTTP разрешён для прямого обращения к адресу интерфейса сервера; он не шифрует данные.
Для недоверенной сети используйте HTTPS. Неизвестные Host и недоверенные proxy-заголовки
не разрешаются автоматически. Явные пользовательские IP/Host-ограничения сохраняются.
Если соединение не устанавливается, проверьте маршрутизацию/firewall ОС; приложение
не меняет их автоматически. Отказ 403 и отказ TCP — разные ситуации.

## Администратор и первый вход

Если администратор **уже создан**, сразу откройте `/login` по сетевому URL и войдите
прежними логином/паролем. Повторная настройка и одноразовый код вам не нужны.

При **новой установке** откройте `/setup` прямо по сетевому адресу. На сервере получите
одноразовый код владельца:

```sh
"$HOME/ProjectTimeMachine/bin/ptm" setup-code
```

Для custom prefix используйте его `bin/ptm`. Введите код в мастере, выберите язык,
задайте свои логин и пароль (не менее 12 символов), подтвердите пароль. Код используется
один раз и удаляется после создания администратора. Код не передаётся в URL и не пишется
в серверный лог. Стандартной пары admin/admin нет. Локальная настройка тоже поддерживается.

## Работа с проектами

1. В **Проекты → Добавить** укажите имя и абсолютный путь к каталогу на сервере. HOME
   текущего пользователя разрешён как родитель: вложенные проекты добавляются без CLI.
   Саму установку PTM, её данные/ключи/архивы зарегистрировать как исходники нельзя.
2. Выберите проект и создайте **Full Backup**. Дождитесь статуса успешного завершения.
3. После изменений создавайте **Incremental** или **Checkpoint**. Снимки сравниваются
   в разделе «Сравнение»; metadata-only снимок не гарантирует восстановление содержимого.
4. Для возврата откройте «Восстановление», выберите backup/snapshot с содержимым,
   режим всего проекта/файлов/новой папки. Проверьте preview и подтвердите RESTORE.
   Перед перезаписью создаётся проверенная страховая копия. Остановите процессы,
   которые пишут в восстанавливаемый проект. Первая проба — на небольшом тестовом каталоге.
5. В Backups настройте ежедневное/еженедельное расписание. Автоматическая очистка выключена.
6. Analysis/Audit показывают анализ без автоисправления; Logs/SQLite — ограниченный просмотр
   с маскировкой распознаваемых секретов. SQLite открывается для просмотра, не редактирования.
7. В Users создавайте Viewer/Operator, выдавайте только нужные проекты и отдельное разрешение
   restore. В Settings меняются язык (ru/en/pl/uk), тема и масштаб.

В «Проекты → Редактировать → Исключения» добавляйте относительные пути нестандартных
виртуальных окружений, например `data/voice/tts_venv`. Стандартные `venv` и `.venv` уже
исключены; произвольные имена автоматически не исключаются. Символические ссылки и
специальные файлы останавливают backup с понятной ошибкой, а не копируются за пределы проекта.

## Настройки и управление

```sh
"$HOME/ProjectTimeMachine/bin/setup"
"$HOME/ProjectTimeMachine/bin/ptm" status
"$HOME/ProjectTimeMachine/bin/ptm" start
"$HOME/ProjectTimeMachine/bin/ptm" stop
"$HOME/ProjectTimeMachine/bin/ptm" restart
```

Из распакованного комплекта также работают `./setup.sh` и `./setup.sh --prefix "$HOME/MyPTM"`.
Меню меняет корни проектов, папку будущих backups, bind, порт, запуск после установки
и отдельный автозапуск user-service при загрузке. Изменения требуют Save. Enter в IP/port
сохраняет текущее значение. Старые архивы не удаляются и не перемещаются.

Явное выключение сети администратором сохраняется после обновления. Владелец установки
может восстановить доступ с терминала без туннеля и без сброса учётных записей:

```sh
"$HOME/ProjectTimeMachine/bin/ptm" network-on
# Для отключения: bin/ptm network-off
```

Дополнительный root проектов можно добавить в setup (абсолютный путь или ~/). Системные
и credential-каталоги/symlink-пути защищены. Служба автозапуска — только своя systemd user
unit, лишь при явном выборе; linger может требовать разрешения ОС. Другие службы не меняются.

## Обновление и удаление

Распакуйте новый комплект отдельно и запустите:

```sh
./install.sh --prefix "$HOME/ProjectTimeMachine"
```

Прежние пользователи, ID, история, archives и настройки сохраняются. Bind/port сохраняются;
если прежде был выбран 127.0.0.1, измените bind на 0.0.0.0 через setup. Ошибочный app_root
старых версий не требует ручной правки или ссылок. Перед миграциями создаётся SQLite checkpoint.
При прерванном update: `bin/ptm recover-update`; при прерванном Save: `bin/setup --recover`.
Затем запуск выполняется явно. После завершённого update автоматического downgrade БД нет.

```sh
"$HOME/ProjectTimeMachine/bin/ptm" uninstall
```

Удаление отключает свою копию и launchers; БД, проекты, archives, keys и код возврата
сохраняются. Не стирайте каталог данных, если хотите сохранить историю.
