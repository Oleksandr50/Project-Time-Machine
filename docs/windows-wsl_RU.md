# Windows 10/11: установка и запуск через WSL2

PTM работает внутри Ubuntu в WSL2, а браузер открывается в Windows. Нативной
Windows EXE-сборки нет. Docker и Python для Windows не нужны.

Эта инструкция относится к исправленной копии исходников с файлом
`scripts/windows-wsl.ps1`. Скачайте [исходники ветки main](https://github.com/Oleksandr50/Project-Time-Machine/archive/refs/heads/main.zip)
или клонируйте репозиторий. Сохраните структуру каталогов целиком. Исходники тега
v0.7.7 предшествуют этим исправлениям: выбирайте main, а не архив исходников тега. Linux-архив
`project-time-machine-0.7.7-linux.tar.gz` не содержит Windows-скриптов.

## 1. Установите WSL2 и Ubuntu

Подходит Windows 11 либо Windows 10 версии 2004, сборки 19041 и новее.
Виртуализация должна быть включена. Официальная инструкция:
[Microsoft — установка WSL](https://learn.microsoft.com/ru-ru/windows/wsl/install).

Только первоначальную установку WSL выполните в PowerShell от администратора:

```powershell
wsl --install -d Ubuntu-24.04
```

Перезагрузите Windows, если появится такое требование. Откройте Ubuntu из меню
«Пуск», создайте обычного Linux-пользователя и пароль. Не используйте root.
В обычном PowerShell проверьте:

```powershell
wsl --list --verbose
```

Для выбранной Ubuntu в колонке VERSION должно быть **2**. Если указано 1, сначала
сохраните резервную копию важных данных дистрибутива и только затем самостоятельно
выполните `wsl --set-version Ubuntu-24.04 2`. Скрипты PTM не конвертируют,
не сбрасывают и не переустанавливают существующие дистрибутивы.

Если WSL устарел, используйте `wsl --update` по инструкции Microsoft. При блокировке
корпоративной политикой обратитесь к администратору; обход политик не выполняется.

## 2. Подготовьте пакеты Ubuntu

В окне Ubuntu:

```sh
sudo apt update
sudo apt install python3 python3-venv ca-certificates
python3 --version
```

Нужен Python **3.11–3.13**. В Ubuntu 24.04 штатно доступен Python 3.12.
Поддерживается и совместимый Python, установленный через `uv` внутри Ubuntu.
Установщик запускает Bash с окружением входа, чтобы учитывать пользовательский PATH
для `uv`; после его установки сначала откройте новое окно Ubuntu.
Windows Python для этого не используется. Сам PTM устанавливайте обычным
пользователем без sudo; sudo требуется только для установки системных пакетов.

## 3. Запустите установку

Поместите полную исправленную копию исходников в удобный каталог Windows.
В PowerShell перейдите в этот каталог. Пробелы в пути поддерживаются.
Если скачанные файлы заблокированы Windows, сначала убедитесь в доверенности
источника и контрольной сумме, затем разблокируйте файлы:

```powershell
Get-ChildItem -LiteralPath . -Recurse -File | Unblock-File
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\Install-Windows.ps1
```

Установка находится **внутри выбранной Ubuntu**, по адресу
`~/ProjectTimeMachine`. Управляющий файл: `~/ProjectTimeMachine/bin/ptm`.
Это не Windows HOME и не старый каталог `.local/share/project-time-machine`.
Распакованные исходники могут лежать на диске Windows; установленное приложение,
виртуальное окружение и данные должны храниться в Linux-файловой системе WSL.

Для другого каталога и порта:

```powershell
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\Install-Windows.ps1 -Distribution Ubuntu-24.04 -Prefix '~/PTM Custom' -Port 13021
```

`-Prefix` принимает Linux-путь либо `~/...`, но не `C:\...` и не `/mnt/c/...`.
Имя дистрибутива должно точно совпадать с выводом `wsl --list --verbose`.
Без `-Port` Linux-установщик выбирает свободный порт при новой установке.
При обновлении сохраняется существующий порт: не передавайте новый `-Port`.
Пользователи, настройки, история и архивы сохраняются штатным механизмом обновления.
Перед обновлением всё равно подготовьте проверенную резервную копию установки.

## 4. Откройте приложение

```powershell
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\Start-Windows.ps1
```

Либо запустите `Start-Windows.cmd` двойным щелчком. Для пользовательской установки
в PowerShell добавьте те же `-Distribution` и `-Prefix`, что использовались при установке.
Из обычной командной строки CMD:

```bat
Start-Windows.cmd -Distribution Ubuntu-24.04 -Prefix "/home/your-linux-user/PTM Custom"
```

Запуск откроет `http://localhost:<фактический-порт>` из статуса PTM.
`0.0.0.0` обозначает интерфейсы прослушивания, а не адрес для браузера.
При проблемах localhost проверьте WSL, VPN и брандмауэр по
[инструкции Microsoft](https://learn.microsoft.com/ru-ru/windows/wsl/networking).
Не открывайте приложение в публичный Интернет ради обхода проблемы.

В мастере создайте собственную учётную запись администратора. Стандартного пароля
нет. Если из-за сетевого проброса Windows мастер запросит код владельца, получите
его в Ubuntu:

```sh
"$HOME/ProjectTimeMachine/bin/ptm" setup-code
```

При другом каталоге замените путь. Не публикуйте код. Для существующей установки
войдите прежним логином и паролем. Проекты из домашней папки Ubuntu доступны через
интерфейс. Диски Windows требуют отдельной настройки разрешённых корней; данная
проверка не подтверждает безопасное восстановление на `/mnt/c`, SMB или NFS.

## 5. Статус, остановка, настройка и удаление

В Ubuntu:

```sh
"$HOME/ProjectTimeMachine/bin/ptm" status
"$HOME/ProjectTimeMachine/bin/ptm" stop
"$HOME/ProjectTimeMachine/bin/setup"
"$HOME/ProjectTimeMachine/bin/ptm" uninstall
```

Подставьте свой путь при установке с `-Prefix`. Штатное удаление отключает PTM,
сохраняя данные, архивы, ключи и прежние релизы. **Не используйте `wsl --unregister`**:
эта команда удаляет весь дистрибутив вместе с посторонними данными. Команда
`wsl --shutdown` останавливает и другие Linux-программы, поэтому PTM её не выполняет.
Автозапуск Windows и глобальные службы этими скриптами не создаются.

## Ошибки и границы проверки

- Нет WSL/Ubuntu либо используется WSL1: выполните шаг 1, данные не сбрасывайте.
- Не хватает Python или venv: проверьте Linux-сообщение и пакеты из шага 2.
- Не найден `bin/ptm`: проверьте дистрибутив и каталог установки.
- Не запускается сервер: ошибка Linux остаётся видимой; смотрите `logs/server.log`
  внутри установки. При ошибке запуска или статуса браузер не открывается.
- PowerShell заблокирован: разблокируйте проверенные файлы либо обратитесь к
  администратору. Машинная политика исполнения не меняется.
- После двойного щелчка окно закрылось: запустите CMD/PowerShell вручную и повторите
  команду, чтобы прочитать диагностику.

Проверки выполнены **на Linux**, включая запуск PowerShell с имитацией WSL,
синтаксис, аргументы и ошибки. Сам CMD проверен статически. Настоящие Windows 10/11,
Windows PowerShell 5.1, `cmd.exe`, ядро WSL2, сетевой проброс и запуск Windows-браузера
в этом испытании не проверялись. Полноценная приёмка на Windows ещё необходима.
