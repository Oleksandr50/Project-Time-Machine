# Анализ, аудит и просмотр данных — этап 6

Анализ читает проект и сохраняет новый Metadata Only snapshot. Он не исправляет файлы,
не запускает код проекта, не устанавливает его зависимости и не вызывает rollback.
Для backup/compare/restore наличие анализатора языка не требуется.

## Анализ кода

В Analysis выберите снимок, функции/классы, категорию файлов и уровень сигнала.
Метрики Active source, Archived data, Generated files, Dependencies показаны отдельно.
Они относятся к выбранному снимку: прошлые результаты с прежними метриками сохранены.
Новая настройка исключений не пересчитывает старую историю.

По умолчанию архивы, зависимости и generated-каталоги исключены общим scanner.
Чтобы сознательно анализировать обычный пользовательский backups-каталог, Administrator
сначала меняет его исключение в Projects, затем включает analyze_archived. Аналогично
для generated/dependencies. Включение категории само по себе не отменяет исключение.
Хранилище приложения и зарегистрированные restore-workspace исключены обязательно.
Категория определяется сегментами пути, а не доказанным происхождением файла;
необычные имена архивных каталогов нужно включать в ручные исключения.

Python использует ast.parse. Исправлены qualified names классов/вложенных функций,
сброс родительского контекста и оценки риска соседних функций. Сгруппированные совпадения
сохраняют список всех строк; сигнал остаётся у каждой затронутой функции.
Импорты файла остаются контекстом зависимостей, но не повышают автоматически риск всех
функций. Обычный subprocess без shell и явный process exit не объявляются Critical.

Встроен Python adapter. `app/analysis_plugins.py` содержит явный registry доверенных
адаптеров: `Adapter(id, extensions, analyze)`, `register`, `for_path`. Код установленного
адаптера должен зарегистрировать его при контролируемом startup приложения. Возвращаются
Entity и findings; дублирующий ID/расширение отклоняется. Совместимая таблица
python_entities сохранена, analyzer_id различает адаптеры. Пример контракта есть в
`tests/test_stage6.py`; загрузки Python из наблюдаемого каталога или UI plugin upload нет.

Адаптер — доверенный код приложения, не песочница для сторонних модулей. Встроенный
AST ограничен 2 MiB/файл, результаты адаптера — 10000 entities/findings на файл.
Ошибки/неподдерживаемые расширения видны в analysis_info и UI. Неподдерживаемый язык
сохраняет структуру, размер, хеши и все основные функции backup/restore.
Нет гарантированного CPU timeout для произвольного установленного адаптера.

## Аудит

Находки — сигналы для ручной проверки, а не подтверждённые уязвимости. В таблице есть
уровень Critical/High/Medium/Low/Info, категория, путь, строки и пояснение. Раскройте
Details для обоснования серьёзности и рекомендации. Код/значение секрета не подставляется
как evidence. Для старых результатов честно указана историческая эвристика; их исходные
уровни и строки не переписываются.

Новые Python-правила используют AST: shell=True/os.system, eval/exec и отдельные unsafe
deserialization API, HTTP timeout на каждом вызове, verify=False, wildcard bind literal,
форматирование SQL в execute-подобном вызове, literal credential assignment, private-key
marker, явный exit. Это ограниченный набор, не taint analysis и не проверка зависимостей.
Базовые import aliases разрешаются, но shadowing/обёртки/динамические имена могут давать
ложные или пропущенные сигналы. Маркер ключа не проверяется как настоящий ключ.

Одинаковая структура правила в одном файле объединяется: fingerprint включает rule,
относительный путь и AST shape без значений литералов и номеров строк. При сдвиге строк
находка остаётся той же; изменение буквального значения само по себе не создаёт новую.
Повторные строки доступны в Lines. Перенос в другой файл считается другой находкой.
Старые дубликаты с NULL lineno группируются при чтении, без удаления исходных записей.
Если у исторических дубликатов разные уровни, показан самый серьёзный из них.

Для сравнения введите ID baseline и выберите All / New / No longer detected / Still
detected. Показаны количества трёх групп. «Больше не обнаружено» может означать изменение
настроек/области/версии анализатора, а не исправление; сравнивайте сопоставимые снимки.
У исчезнувшей находки строки относятся к baseline. Legacy и новые AST identities
различаются: переход анализатора не выдаётся за доказанное исправление уязвимости.

Administrator и Operator назначенного проекта могут отметить false positive или открыть
находку повторно; Viewer только читает. Отметки общие в пределах проекта, применяются к
совпадающим fingerprints других снимков, не меняют severity и исходный finding. Каждый
переход сохраняется в audit_review_events с actor ID и временем; в registry фиксируется
действие пользователя. Указанный браузером user_id игнорируется.
Счётчики уровней и Dashboard суммируют исходные сигналы, включая отмеченные false positive;
для списка требующих проверки используйте Review → Open. Это не счётчик подтверждённых угроз.

Export masked JSON сохраняет выбранные baseline/change/category/severity/review/search
фильтры. Максимум 10000 находок/2 MiB, truncated сообщает усечение. Нет сырых evidence,
исключений Python или содержимого файлов. Старые и новые display/export строки проходят
маскировку. Исходная историческая SQLite может содержать прежние данные; её не очищают
автоматически, она по-прежнему требует защиты ОС и резервного копирования.

## Логи

Logs перечисляет разрешённые .log с размером и датой, поиском/сортировкой/пагинацией списка.
Откройте файл, выберите уровень и текст поиска. Фильтры применяются **после маскировки**
к последним 2 MiB, выводится до 2000 подходящих строк. Частичная начальная строка
отбрасывается, усечение обозначено. Это ограниченный tail, не поиск по всему большому
файлу. Copy копирует только показанный замаскированный фрагмент. Обновление перечитывает
окно; приложение не меняет лог и не управляет процессом, который его пишет.

Ссылки проверяются заново при открытии: allowlist, nofollow, расширение, configured и
обязательные исключения, secret filename, запрет storage/workspace/cross-project path.
Изменение файла во время чтения обозначено; для строгого сравнения остановите writer.

## SQLite

SQLite сначала показывает файлы. Откройте один, затем выберите таблицу и размер страницы
10/25/50/100. Показаны таблицы с count, ограниченные записи и переходы страниц.
Произвольного SQL API/редактора/POST для записи нет.

Рабочая база не открывается SQLite-драйвером, даже с mode=ro: это могло бы создать SHM.
DB/WAL/journal читаются через anchored nofollow FDs в private temp, сверяются наличие,
inode/size/mtime/ctime. Quick check/recovery и Backup API работают только с копиями.
Нормализованная копия открывается mode=ro&immutable=1, query_only, trusted_schema=OFF,
load_extension выключен, record SELECT проходит authorizer. Views, virtual/shadow tables
и generated columns не выполняются. Табличные/колоночные идентификаторы берутся из
проверенного каталога и экранируются, параметры LIMIT/OFFSET связаны.

Лимиты: capture 64 MiB суммарно, deadline 5s, около 100 schema entries, 100 columns,
page до 100000, до 128 KiB/страницу и 4096 символов на cell. BLOB скрыт. Таймауты/порча/
нестабильность приводят к сообщению об отказе, а не записи в исходник. Каждая страница
делает новый capture: при внешних изменениях результаты разных страниц могут различаться.
Это средство просмотра небольших БД, не универсальный database client.

Masking учитывает чувствительные имена колонок/таблиц, key-value rows и известные формы
credential assignment, Bearer/Basic, URL userinfo, private keys/token prefixes. Email,
phone и address columns скрыты. Неизвестные непромаркированные значения нельзя надёжно
распознать эвристикой; до предоставления Viewer доступа проверьте собственные схемы
и используйте project ACL. Вводить реальные секреты в строку поиска не следует.

Source inspection использует общий project lock: backup/restore не меняет состояние
одновременно с таким чтением. Pending interrupted restore блокирует inspection до
явного recovery; анализ также не обходит lease. Просмотр уже сохранённого аудита/метрик
и отметки false positive исходники не трогают.
