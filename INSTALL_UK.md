# Project Time Machine 0.7.6 — Linux

## Встановлення

Потрібні Linux kernel 5.3+, Python 3.11–3.13 із venv, tar/gzip та інтернет для залежностей.
Ubuntu: `sudo apt install python3-venv`. Запускайте інсталятор як звичайний користувач,
без sudo. Вже встановлений Python із uv знаходиться автоматично.

```sh
sha256sum -c SHA256SUMS
tar -xzf project-time-machine-0.7.6-linux.tar.gz
cd project-time-machine-0.7.6
./install.sh
```

Архів можна розпакувати будь-де. Типова папка — `$HOME/ProjectTimeMachine`;
постійні дані відокремлені від коду releases. Інша папка й порт:

```sh
./install.sh --prefix "$HOME/MyPTM" --port 13021
```

Типовий порт 13011; якщо зайнятий, обирається вільний. Явно вказаний зайнятий порт
дає помилку, чужі процеси не зупиняються. `--no-start` пропускає запуск, а
`--wheelhouse /absolute/wheels` використовує локальні пакети. Root не потрібен,
системні служби й firewall не змінюються. Самоперевірка використовує тимчасові дані.

## Прямий доступ через інтерфейси

Типовий bind **0.0.0.0** охоплює всі IPv4-інтерфейси. Інсталятор показує їхні реальні
URL. Відкрийте `http://АДРЕСА_СЕРВЕРА:ПОРТ` через Ethernet/Wi-Fi/VPN, зокрема адреси
100.64.0.0/10. SSH-тунель і ручне додавання підмереж не потрібні. 0.0.0.0 — адреса
прослуховування, не адреса браузера. Для IPv6 оберіть bind `::`.
HTTP не шифрує з'єднання; у недовіреній мережі використовуйте HTTPS. Невідомі Host та
недовірені proxy-заголовки не дозволяються автоматично. Явні IP/Host-обмеження власника
зберігаються. Маршрутизація та firewall ОС автоматично не змінюються.

## Адміністратор

Якщо адміністратора вже створено, відкрийте `/login` і введіть чинні логін/пароль.
Повторне налаштування та одноразовий код вам не потрібні.
Для нової інсталяції відкрийте `/setup` безпосередньо через мережу. На сервері виконайте:

```sh
"$HOME/ProjectTimeMachine/bin/ptm" setup-code
```

Для іншої папки використайте її `bin/ptm`. Введіть одноразовий код власника, оберіть мову,
логін і пароль (щонайменше 12 символів), підтвердьте пароль. Код видаляється після
створення адміністратора, не потрапляє до URL або серверного журналу. Типової пари
admin/admin немає. Локальне налаштування також підтримується.

## Робота

1. Projects → Add: назва та абсолютний шлях до каталогу на сервері. HOME дозволяє
   вкладені проєкти без CLI. Код/дані/ключі/архіви самого PTM захищені.
2. Оберіть проєкт, створіть Full Backup і дочекайтеся успішного завершення.
3. Після змін створюйте Incremental або Checkpoint; Compare показує відмінності знімків.
   Metadata Only не гарантує відновлення вмісту.
4. Restore: backup/відновлюваний snapshot, весь проєкт/файли/нова папка. Перевірте preview
   та явно підтвердьте RESTORE. Перед перезаписом створюється перевірена страхова копія.
   Зупиніть процеси, що пишуть у проєкт. Першу пробу робіть на малому тимчасовому каталозі.
5. Backups: щоденний/щотижневий розклад; автоматичне видалення типово вимкнене.
6. Analysis/Audit не виправляють вихідні файли автоматично. Logs/SQLite — обмежений
   перегляд із маскуванням розпізнаних секретів; SQLite не редагує записи.
7. Users: Viewer/Operator, дозволені проєкти та окремий дозвіл restore.
   Settings: ru/en/pl/uk, тема та масштаб.

У «Проєкти → Редагувати → Виключення» додайте відносні шляхи віртуальних середовищ із
власними назвами, наприклад `data/voice/tts_venv`. Стандартні `venv` і `.venv` уже виключені;
інші назви автоматично не виключаються. Символічні посилання та спеціальні файли зупиняють
backup зі зрозумілою помилкою, а не копіюються за межі проєкту.

## Налаштування й керування

```sh
"$HOME/ProjectTimeMachine/bin/setup"
"$HOME/ProjectTimeMachine/bin/ptm" status
"$HOME/ProjectTimeMachine/bin/ptm" start
"$HOME/ProjectTimeMachine/bin/ptm" stop
"$HOME/ProjectTimeMachine/bin/ptm" restart
```

Із розпакованого комплекту працюють `./setup.sh` і `./setup.sh --prefix "$HOME/MyPTM"`.
Меню змінює корені проєктів, папку майбутніх backup, bind, порт, запуск після встановлення
та автозапуск. Save зберігає зміни. Порожній Enter залишає IP/порт. Старі архіви не
переміщуються й не видаляються. Створюється лише своя systemd user-unit за явним вибором;
linger може вимагати дозволу ОС. Інші служби не змінюються.

Явне вимкнення мережі адміністратором зберігається після оновлення. Власник може відновити
доступ із термінала без тунелю та без скидання облікових записів:

```sh
"$HOME/ProjectTimeMachine/bin/ptm" network-on
# Вимкнення: bin/ptm network-off
```

Додаткові корені приймають абсолютні шляхи та ~/. Системні/credential-каталоги й
symlink-шляхи захищені.

## Оновлення та видалення

Розпакуйте новий комплект окремо:

```sh
./install.sh --prefix "$HOME/ProjectTimeMachine"
```

Користувачі, ID, історія, архіви, налаштування та bind/порт зберігаються. Якщо раніше
було обрано 127.0.0.1, змініть bind на 0.0.0.0 у setup. Старий помилковий app_root не
потребує ручного редагування або посилань. Перед міграціями є SQLite checkpoint.
Перерване оновлення: `bin/ptm recover-update`; перерване збереження: `bin/setup --recover`,
потім явний запуск. Після завершеного оновлення автоматичного downgrade БД немає.

```sh
"$HOME/ProjectTimeMachine/bin/ptm" uninstall
```

Команда вимикає свою копію та launchers. БД, проєкти, backup, ключі й код повернення
зберігаються. Не стирайте дані, якщо потрібна історія.
